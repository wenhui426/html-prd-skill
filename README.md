# html-prd

将已有 HTML 网页或交互原型整理为产品需求文档（PRD），支持 Markdown 文档和带页面侧边说明的 HTML 评审版。

将整个 `html-prd/` 文件夹复制给使用者即可。运行时读取 `SKILL.md`；Python 脚本使用标准库，无需安装第三方包。

## 输入与输出

输入支持单个 HTML 文件或多页面 HTML 目录。请保留页面引用的 CSS、JavaScript、图片、字体和本地数据文件；可同时提供业务描述、旧文档、截图和规则说明。

| 输出选择 | 产物 | 用途 |
| --- | --- | --- |
| Markdown | `PRD.md` | 独立阅读、编辑、归档产品方案 |
| HTML 评审版 | `PRD评审版.html` | 选择并列可调或聚焦抽屉；优先生成可单独双击、随原型切页同步说明的单文件 |
| Markdown 与 HTML 都要 | `PRD.md` 加本次选定的 HTML 布局文件 | 共用已确认文案，分别用于文档流转和页面评审 |

输出目录由用户在开工时指定，正式产物和 `过程记录/` 都放在该目录；可与输入 HTML 位于同一目录。HTML 评审版生成新文件，原页面及其依赖保持不变。单文件方案无法完整承载原型时，先说明阻碍，由用户决定是否接受配套文件。

### 每次任务的输出目录

正式产物放在用户指定的输出目录根部；中途恢复所需的记录放在同目录的 `过程记录/`。例如同时选择 Markdown 和一种 HTML 布局时：

```text
<输出目录>/
├── PRD.md                         # 正式 Markdown 文档
├── PRD评审版.html                # 正式 HTML 评审版
├── <HTML 必需的配套文件>         # 仅在用户同意外部引用模式时出现
└── 过程记录/                     # 中断续做使用；交付后保留
    ├── progress.json             # 输入、输出选择、当前页、总页数、逐页状态和阶段
    ├── 页面清单.md                # 已确认的页面范围、顺序、来源和处理状态
    ├── pages/                     # 各页正文或尚待确认的草稿
    │   ├── P01.md
    │   └── P02.md
    ├── source-hashes.json         # 执行源文件快照时生成
    └── validation-report.json    # 执行产物校验时生成
```

若两种 HTML 布局都选，根部改为 `PRD评审版-并列可调.html` 和 `PRD评审版-聚焦抽屉.html`；若只选一种输出形式，根部只保留该形式及其必要配套文件。`source-hashes.json` 和 `validation-report.json` 仅在相应检查执行后存在。“无需说明”页只在页面清单与进度中留状态，不创建空白的单页正文。

每确认一页，就保存该页正文并更新 `progress.json`。未确认草稿可以保存，但状态仍是“待确认”。下次继续时，先核对过程记录和输入文件，再从首个未确认页面接着做；记录不完整时先与用户核对，不直接猜测进度。用户明确要求先跳过并生成当前版本时，跳过页记为“跳过（未确认）”：Markdown 只有清单行，HTML 保留原型入口并提示“本页说明未确认”。这种产物标为阶段性版本，交付摘要列出未完成页面；过程记录不会在交付时自动清理。

选择 HTML 时，还需确认评审布局。**并列可调**让原型与当前页全部说明常驻，可拖动分隔线或选择 70/30、60/40、50/50 比例；**聚焦抽屉**默认让原型占满，点击按钮后在右侧抽屉中连续展示当前页全部说明。两种布局都没有说明分类筛选和逐条翻页。可以同时生成两种布局；此时文件名分别为 `PRD评审版-并列可调.html` 和 `PRD评审版-聚焦抽屉.html`。

每次启动都会展示三种输出选项；选择 HTML 时，还会展示两种布局及“两种布局都要”，等待用户确认本次选择。不会沿用上次任务的选择。开工确认还会列出 HTML 输入、输出目录、三份模板路径和可选补充材料，已知信息会直接填入。

## 模板替换

三份模板用途独立，均可在开工时给出替代文件路径；不需要改动 Skill 内置文件。未指定替代文件的部分继续使用默认模板。

| 模板 | 默认文件 | 负责内容 |
| --- | --- | --- |
| 逐页说明 | [页面说明模板.md](assets/页面说明模板.md) | 生成单页说明草稿时的默认章节；每页可裁剪 |
| Markdown PRD | [PRD模板.md](assets/PRD模板.md) | 整份文档的章节骨架；页面正文作为一个内容块插入 |
| HTML 评审版 | [PRD评审版模板.html](assets/PRD评审版模板.html) | 目录、说明和两种布局的页面壳；单文件交付时还需按原型导航方式内联适配 |

替换 Markdown 或 HTML 模板时，助手按替代文件的结构放入已确认内容，不要求它复用默认逐页模板的章节名。替换 HTML 模板仍需保留所选布局、原型操作、页面目录和说明同步。三份模板只传递“已确认的页面正文”，没有相互复制的章节结构。

流程中也可更换模板：新的逐页模板用于尚未确认的页面；新的输出模板用于随后生成的文件。已确认的页面正文不会因换模板自动改写。

使用时可以直接说：`逐页模板用 <我的页面模板路径>；Markdown 模板用 <我的 PRD 模板路径>；HTML 模板用 <我的评审模板路径>。P03 到时用我提供的正文，不套逐页模板。` 只替换其中一份时，其余两份继续使用默认文件。

## 如何使用

向助手提供 Skill 路径、HTML 输入路径、输出方式和输出目录，例如：

```text
请使用 html-prd，把 <原型 HTML 路径> 整理为 PRD。
Markdown 和 HTML 评审版都要；HTML 选并列可调，输出到 <本次输出目录>。
先确认页面清单，再逐页生成说明；每页等我确认和修正后继续。
```

如果当前助手已安装并支持按名称调用该 Skill，也可以直接使用 `$html-prd`。

## 工作流程

1. 展示开工确认卡；本次明确选择输出方式及 HTML 评审布局，并确认 HTML 输入、输出目录和三份模板路径。
2. 检查页面文件、依赖、实际交互和页面状态。
3. 展示页面清单与处理顺序，等待用户确认。
4. 每次生成一页完整说明，在对话中展示。
5. 用户确认或提出修正；修正后再次确认，再进入下一页。
6. 全程同步保存 `过程记录/`；所有页面确认后生成用户选择的产物。若用户明确要求先跳过未确认页，可生成标明缺口的阶段性版本。
7. 检查文件和页面映射，交付时逐项列出待确认事项与运行限制。

用户可以确认一页文案，同时保留其中尚未解决的待确认项。不适用的文档模块经用户确认后移除。

页面保留在评审范围、但不需要说明时，标记“无需说明（已确认）”：Markdown 只在页面清单保留一行，不生成该页详细章节；HTML 保留原型和目录入口，说明区显示“本页无评审说明”，不会沿用上一页内容。

某页需要直接采用使用者提供的文字时，可在开工时指定页码，也可处理到该页再说明。该页跳过逐页模板，按提供的内容及结构展示给使用者确认；只有页面编号、导航和 HTML 容器等必要结构由 Skill 补齐。

用户补充的需求与现有 HTML 不一致时，文档记录需求差异，明确区分当前实现和用户确认的要求。

## 文件结构与用途

```text
html-prd/
├── SKILL.md                         # 助手执行入口：触发范围、流程、逐页确认和交付规则
├── README.md                        # 使用说明：输入输出、用法、文件结构与当前限制
├── LICENSE                          # MIT 许可证
├── assets/                          # 生成产物时使用的通用模板
│   ├── PRD模板.md                   # Markdown PRD 的文档级骨架，不限定单页正文结构
│   ├── 页面说明模板.md               # 逐页说明的默认结构，可复制、裁剪或替换
│   └── PRD评审版模板.html           # 并列可调／聚焦抽屉双布局、页面目录与同步脚本
├── references/                      # 执行时按需读取的补充规范
│   ├── 交付摘要与检查.md            # 模板填充规则、编号约定、校验用法和交付回复格式
│   └── 单文件评审版.md              # 原型内联、页面同步、直开验收及失败边界
├── scripts/                         # 可重复执行的检查工具
│   ├── validate_outputs.py          # 受保护文件哈希、产物结构、页面及待确认编号检查
│   ├── build_single_file_review.py  # 自包含单 HTML + hash 路由的单文件评审版生成
│   └── preview_review.py            # 外部引用模式的本机同源预览工具
```

旧版打磨记录和测试素材不属于分享文件夹；接收方只需本目录中的文件。

## 输出校验

校验脚本使用 Python 标准库，需要 Python 3.10 或更新版本。在本 Skill 目录下执行：

```powershell
python scripts/validate_outputs.py snapshot --source "<输入文件或目录>" --manifest "<输出目录>/过程记录/source-hashes.json"

# 生成产物后检查 Markdown、选定的 HTML 布局及源文件完整性
python scripts/validate_outputs.py check --source "<输入文件或目录>" --output-dir "<输出目录>" --mode both --manifest "<输出目录>/过程记录/source-hashes.json" --report "<输出目录>/过程记录/validation-report.json"
```

如果输入和输出使用同一文件夹，`snapshot` 时增加 `--exclude "过程记录"` 和已有正式产物的 `--exclude` 参数。自包含单 HTML 也可以直接把 `--source` 指向该 HTML；这时只校验这个文件。

参数说明：

| 参数 | 用途 |
| --- | --- |
| `--source` | 哈希校验的文件或目录；单文件只保护该文件，建议传入包含 HTML 与本地依赖的目录 |
| `--exclude` | `snapshot` 时排除已有产物、过程记录等非输入文件；可重复使用 |
| `--manifest` | 生成前记录的源文件哈希清单 |
| `--output-dir` | 产物所在目录 |
| `--mode` | `md`、`html` 或 `both` |
| `--prd-name` | 自定义 Markdown 文件名，默认 `PRD.md` |
| `--review-name` | 自定义 HTML 文件名，默认 `PRD评审版.html` |
| `--report` | 可选，保存 JSON 检查报告 |

脚本可以检查占位符、源文件哈希、本地原页面路径、页面目录与说明区编号，以及双产物的页面和待确认编号一致性。文案准确性、逐页确认记录和实际浏览器交互仍需助手与用户检查。

同时生成两种 HTML 布局时，分别用 `--review-name "PRD评审版-并列可调.html"` 和 `--review-name "PRD评审版-聚焦抽屉.html"` 运行检查，`--report` 分别保存为 `validation-report-并列可调.json`、`validation-report-聚焦抽屉.json`；有 Markdown 时两次均用 `--mode both`。脚本只比对页面和待确认编号，仍需回读正文核对措辞。

## HTML 评审版的自动同步

默认交付目标是单文件直开：只复制最终评审 HTML 到空目录，双击打开后，从原型内部切页和返回时，说明与目录应同步。自包含、通过 hash 切页的单个 HTML 可用 `scripts/build_single_file_review.py` 生成；页面映射格式和命令见 [单文件评审版.md](references/单文件评审版.md)。其他原型先检查资源和导航，再适配。

原型无法完整内联时，先向使用者说明阻碍。经使用者同意保留外部依赖后，才使用本机同源预览。把下面的目录与文件名换成本次产物的实际路径：

```powershell
python scripts/preview_review.py --source-root "<原型目录>" --output-dir "<输出目录>" --review-name "PRD评审版.html"
```

命令会打开浏览器；可识别的原型内部链接、目录和返回操作会同步右侧说明。服务只监听本机，只允许读取指定的源目录和输出目录，关闭命令窗口或按 Ctrl+C 即停止；两目录须在同一盘符。此模式直接双击 HTML 时，浏览器可能阻止识别原型内部跳转，评审版会清除旧备注并提示手动选页。交付时须标明这一限制。

默认 Markdown PRD 保留文档章与 Pxx 页面编号；页面说明项以加粗行呈现，不再加 1、2、3 小节序号。用户提供自由正文的页面保留其原有结构。

## 当前限制与验证状态

- 必需输入为已有 HTML；描述、文档和截图可作为补充材料。
- 目前提供页面级说明；元素高亮联动尚未实现。
- 单文件脚本覆盖自包含、hash 切页的单个 HTML；动态请求、登录态、跨域内容和复杂本地资源需逐项分析。内置 HTML 模板也是外部引用模式的页面壳。
- 外部引用模式需保留原页面和相关资源路径；`file://` 下可能无法读取 iframe 地址。无法识别时应清除旧备注，避免显示错误说明。
- 使用单文件脚本后仍需在浏览器中检查原型内部前进、返回、评审目录切页、布局操作及外部资源请求。

## 后续替换与升级

提供项目资料后，可分别升级 Markdown 章节结构、HTML 评审布局、页面说明模板和检查规则。对应文件集中在 `assets/`、`references/` 和 `scripts/`，执行流程在 `SKILL.md` 中维护。
