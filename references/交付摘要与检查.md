# 交付摘要与检查

在准备最终文件和交付检查时读取本文件。过程记录的保存与续做规则见 `SKILL.md` 的“输出目录与过程记录”。

## 生成前后的源文件保护

源 HTML 及其依赖必须保持不变。需要可复核证据时，`<校验目录>`选包含本次 HTML 与本地依赖的最小共同目录，生成前记录哈希，生成后再检查：

```powershell
python scripts/validate_outputs.py snapshot --source "<校验目录>" --manifest "<输出目录>\过程记录\source-hashes.json"
python scripts/validate_outputs.py check --source "<校验目录>" --output-dir "<输出目录>" --mode both --manifest "<输出目录>\过程记录\source-hashes.json" --report "<输出目录>\过程记录\validation-report.json"
```

- `--mode` 可用 `md`、`html`、`both`。
- 生成两种 HTML 布局时，对两份文件分别运行 `check`，通过 `--review-name` 指定 HTML 文件名，同时把 `--report` 分别设为 `validation-report-并列可调.json`、`validation-report-聚焦抽屉.json`；若同时生成 Markdown，两次都使用 `--mode both` 检查编号一致性，避免第二次报告覆盖第一次。
- 单个 HTML 文件作为分析输入时，校验仍应传包含它及本地 CSS、JavaScript、图片等依赖的目录。传入单文件路径只检查该文件；目录外或动态加载的依赖未自动纳入时，交付时说明。
- 输入目录与开工时指定的输出目录相同时，`snapshot` 加上 `--exclude "过程记录"`、`--exclude "PRD.md"` 及本次可能存在的评审 HTML 文件名；输入目录包含输出子目录时，排除该输出子目录。排除项只用于非输入文件，不得排除原型依赖。
- `过程记录/` 是持久目录，不是临时目录。无法执行哈希对比时不伪造清单，交付时说明未执行。
- 哈希清单和检查报告不是用户选择的 PRD 产物；交付后保留过程记录，不自动删除。

## 模板使用要求

- 逐页正文、Markdown 骨架、HTML 页面壳分别读取本次确认的模板路径；用户未替换时，使用 `assets/页面说明模板.md`、`assets/PRD模板.md`、`assets/PRD评审版模板.html`。不要改动这些模板原件。
- 自定义逐页模板只影响需要生成说明的页面；用户指定“该页使用我的内容”时，保留其正文结构并跳过逐页模板。
- 自定义 Markdown 模板可以自行设计章节，只需保留经确认的页面清单、页面正文、差异和待确认内容。自定义 HTML 模板可以自行设计样式，只需保留可操作原型、页面目录、说明同步及本次所选布局。不要求三份模板使用相同章节名或占位符。
- 内置校验脚本识别 HTML 中的 `iframe`、带 `data-page` 的目录按钮、带 `data-page` 的 `article`/`section` 说明面板，以及 `activatePage` 或 `showPage` 切换函数。单文件版若使用其他原型承载或页面映射结构，应先适配校验脚本或提供同等强度的定向检查，并在隔离目录用 `file://` 实际切换页面；不得把脚本校验失败当作通过。
- 使用内置 Markdown 模板时，`{{PAGE_INDEX_ROWS}}` 填页面清单行，`{{PAGE_SECTIONS}}` 填需要说明的已确认页面正文。逐页模板的章节直接写入该区域，不再用 Markdown 模板重复定义一次。
- 默认页面说明写入 `## 4. 页面需求说明` 时，`Pxx 页面名称`使用三级标题，模板说明项使用独立加粗行且不带小节序号；自由正文的内部标题下调到 Pxx 的下一层，保留章节名称、顺序和正文，过程记录不改用户原文。
- 将 `{{REVIEW_LAYOUT}}` 填为 `parallel`（并列可调）或 `drawer`（聚焦抽屉）。仅生成一种布局时默认文件名为 `PRD评审版.html`；两种同时生成时用 `PRD评审版-并列可调.html`、`PRD评审版-聚焦抽屉.html`。
- 替换全部 `{{...}}` 占位符。
- 页面编号使用 `P01`、`P02`；待确认项使用 `Q01`、`Q02`；需求差异使用 `D01`、`D02`。
- Markdown 与 HTML 同时输出时，页面编号、待确认编号和文案保持一致。校验脚本只自动比对编号；逐页正文及可见待确认问题需回读核对。
- 删除无内容或用户确认不适用的章节，不保留空模板。
- “无需说明”页面在 Markdown 只占页面清单一行，说明状态写“无需说明（已确认）”；不创建页面正文标题或空白章节。HTML 保留目录按钮和原型来源，说明面板仅放中性提示；该提示不是 PRD 说明正文。
- 用户明确要求生成阶段性版本时，“跳过（未确认）”页面也只占 Markdown 清单一行；HTML 保留目录按钮和原型来源，说明面板只放“本页说明未确认”。交付摘要逐页列明，不把它计入已确认数。

HTML 模板中的导航项和页面说明使用以下结构：

```html
<button type="button" data-page="p01" aria-current="page">P01 页面名称</button>

<article class="note-panel active"
         data-page="p01"
         data-name="P01 页面名称"
         data-source="../原页面/index.html">
  <h2>P01 页面名称</h2>
  <!-- 写入该页已确认说明，待确认项保留 Q 编号 -->
</article>
```

“无需说明”页使用相同的导航与面板映射，面板中只放状态提示：

```html
<article class="note-panel" data-page="p02" data-name="P02 页面名称"
         data-source="../原页面/page-02.html" data-review="none">
  <p>本页无评审说明</p>
</article>
```

跳过页使用相同映射，`data-review="pending"`，提示文案为“本页说明未确认”。

外部引用模式下，`data-source` 相对于最终 `PRD评审版.html` 计算。单文件模式应把可内联的原型数据放入生成的评审文件，并用稳定的视图标识建立页面映射；不要向源 HTML 注入评审脚本。具体做法与验收见 [单文件评审版.md](单文件评审版.md)。

两种布局都把当前页说明完整写在同一个 `article.note-panel` 内。并列版直接平铺展示，不加入分类筛选或逐条折叠；抽屉版打开后完整展示该页说明，不做逐条翻页。页面清单和说明内容应与 Markdown 及另一布局保持一致。

自由内容页仅在外层补 `article.note-panel` 的页面映射属性；正文内部按用户确认的结构输出。用户提供 Markdown 时可转换成等价 HTML，不自动补默认逐页章节。能够读取到原型跳入未收录页面时，内置模板会清除前页说明并显示范围提示。

同一个 HTML 文件承载多个视图时，单文件模式应检查原型现有视图切换入口或状态，建立稳定映射并验证原型内切页与说明同步。外部引用模式下，若各视图有可辨识的 hash 或查询参数，可分别写入 `data-source`；若视图状态没有反映在 URL 中，说明自动识别限制，不冒充同步成功。

单文件模式需把最终 HTML 独立放到空目录，以 `file://` 直开，并从原型内部点击前进、返回，逐次核对说明与目录选中状态。外部引用模式才使用 `scripts/preview_review.py` 同源打开源目录与输出目录；若直接双击造成地址不可读，切页后应清除旧说明并提示手动选择。交付摘要区分两种模式和各自限制。

## 最终回复模板

最终回复必须逐项列出待确认内容。只写“还有 3 项待确认”不满足交付要求。

```markdown
已生成并检查完成。

交付物：
- [PRD.md](完整路径)
- [PRD评审版.html](完整路径)

确认进度：
- 已确认页面：X / X
- 跳过（未确认）：无 / 逐页列出编号与影响

过程记录：
- [过程记录](完整路径)，可据此继续未完成页面或核对本次确认历史

待确认事项：
- Q01：具体问题（影响页面或规则）
- Q02：具体问题（影响页面或规则）

运行限制：
- HTML 模式：单文件直开 / 外部引用；具体限制及影响，没有则写“无已知限制”。

检查结果：
- 源文件：哈希一致 / 未执行哈希对比
- Markdown：通过 / 未选择
- HTML 评审版：通过 / 未选择
```

仅列出用户选择的交付文件；若两种 HTML 布局都生成，在“交付物”和“检查结果”中分别列出两份评审版。

如果没有待确认项，明确写“无待确认项”，不要省略该段。
