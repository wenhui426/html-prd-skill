# 单文件 HTML 评审版

选择 HTML 输出时读取本文件。目标是最终评审 HTML 单独复制到其他目录后，用户直接双击打开，原型交互仍能切页，右侧说明跟随当前页面。不得以“启动本地服务后可用”替代这个验收条件。

## 生成前判断

1. 盘点页面入口、视图数据、HTML/CSS/JS、图片、字体、动态请求、跨域内容和导航方式。确认哪些资源可以合法且完整地放进新文件。对无法取得、依赖服务端、需要登录态或受浏览器安全限制的内容，记录具体影响。
2. 识别每个评审页面的稳定标识，并建立“原型视图标识 → Pxx 说明”映射。一个 URL 承载多个视图时，不能只靠 iframe 地址判断当前页；检查原型是否已有可调用的导航函数、路由事件或视图状态。
3. 对可内联的原型，优先复用原有视图数据和交互代码，在生成副本中建立统一切页入口。原型内部跳转、返回和评审目录选页都应走该入口，并在切换成功后更新 Pxx 说明及目录选中项。只修改生成副本，不修改输入文件。
4. 检查原型中的相对路径和指向虚拟 `.html` 页面的跳转。内联后这些路径可能失效；只对实际存在且可确定目标的路径做适配。涉及服务端行为、跨域或目标不明时保留限制说明，不猜测跳转目标。
5. 将所需的页面数据、脚本、样式和可用资源放入新 HTML；内联脚本中的 `</script>` 等终止序列须安全处理。注意图片、字体、CSS `url(...)`、`fetch`、ES module、Web Worker 等仍可能产生外部请求；不能只因为 HTML 文件只有一个就声称“无依赖”。

## 与内置模板的关系

`assets/PRD评审版模板.html` 提供布局、右侧目录、说明区和外部引用模式的起点。单文件交付时保留本次选择的布局与说明结构，将其中的 `iframe src="{{FIRST_PAGE_SOURCE}}"`、按 iframe URL 识别页面的脚本，改为本次原型实际可用的内联承载和视图事件。也可以使用用户提供的 HTML 模板。不要复制某个测试项目的页面数据、文件名、导航函数名或五处链接适配规则。

### 自包含单 HTML + hash 路由

此类原型可用 `scripts/build_single_file_review.py` 完成常见的内联和说明同步。先在本次输出目录的 `过程记录/review-pages.json` 记录已确认的页面映射，例如：

```json
{
  "pages": [
    {"id": "P01", "name": "工作台", "match": "#overview", "note": "pages/P01.md"},
    {"id": "P02", "name": "问题详情", "match": "#detail/", "navigate": "#detail/ITEM-001", "note": "pages/P02.md"}
  ]
}
```

`match` 为完整 hash；以 `/` 结尾时按前缀匹配。`navigate` 是点击评审目录时原型要打开的具体 hash，省略时使用 `match`。详情页等动态路由应填写可打开的具体目标。`note` 相对于映射文件所在目录，指向已确认的单页正文。无需说明页把 `status` 写为 `无需说明（已确认）` 并省略 `note`；阶段性跳过页写 `跳过（未确认）`。

```text
python scripts/build_single_file_review.py --source "<自包含原型.html>" --pages "<输出目录>/过程记录/review-pages.json" --output-dir "<输出目录>" --layout both
```

`--layout` 可选 `parallel`、`drawer`、`both`。单布局生成 `PRD评审版.html`，双布局生成两份带布局名的文件。默认拒绝覆盖已有同名文件；仅确认属于本次任务、需要重新生成时使用 `--force`。脚本使用 Python 标准库，接受内置模板、简单 Markdown 逐页正文和无本地／远程依赖的单个 HTML。检测到外部资源或动态请求时停止，按“生成前判断”处理。复杂 Markdown 或自定义 HTML 模板需人工检查并适配，不能以脚本通过代替浏览器验收。

生成文件中的目录项与说明面板仍应使用一致的 `data-page="p01"` 等编号，方便交叉检查。若不再使用 `data-source` 指向外部页面，移除该属性或改用不会被误判为文件路径的视图标识；保留可识别的原型视图映射。不要保留已经失效的 `src`、旁置脚本引用或“需要同源预览”的文案。

## 验收

1. 把最终 HTML 单独复制到只含该文件的目录，以 `file://` 直接打开。不能使用开发服务器、本地代理或浏览器放宽安全限制的启动参数代替。
2. 检查初始原型、当前页说明和目录选中项一致；从原型内部执行一次前进和返回；再从评审目录选页。复杂原型要覆盖不同导航方式和关键页面。
3. 检查页面切换后说明无残留。“无需说明”只显示中性提示；“跳过（未确认）”只显示未确认提示；范围外或无法识别的页面要清空上一页说明。
4. 检查网络请求、控制台异常、资源显示和可操作交互。检查并列布局拖动及比例、抽屉布局打开及完整说明滚动。必要时重启浏览器再次直开。
5. 记录本次覆盖和未覆盖的交互。不能将一个原型的单文件试跑结果当作其他原型已通过。

## 无法单文件化时

向用户列明阻碍、受影响页面和可选处理方式，等待其决定。用户同意保留外部依赖后，可沿用内置模板的 `iframe src` 模式及 `scripts/preview_review.py` 同源预览；交付时列出必需文件与启动方法，并明确双击打开时是否能同步。若用户坚持只收单文件且原型依赖无法内联，停止 HTML 交付并保留已确认的页面说明与过程记录，不伪造可用产物。
